02 Realtime contract

No allocation. No locks. No excuses.

The callback owns a preallocated mix buffer and a fixed voice pool. Commands arrive through a bounded ring. Structural edits are built on the control thread and swapped at a block boundary, so the render path never waits on a mutex.

The displaced graph travels back through a second ring. The control thread drops it. Destruction is off the audio path, and the callback stays bounded.

// Illustrative sketch, not shipped source.
fn callback(&mut self, out: &mut [f32]) {
    self.commands.drain(|cmd| self.apply(cmd)); // bounded
    self.transport.advance(512);          // 960 PPQ
    self.voices.render(&mut self.mix);       // fixed pool
    self.master.process(&mut self.mix);      // inserts
    self.limiter.process(&mut self.mix);      // ceiling
    out.copy_from_slice(&self.mix);              // 512 frames
    self.garbage.publish(self.retired());        // off-path drop
}

The real engine is split across crates and uses its own command enum, transport and processor traits. This sketch shows the shape of the contract, not the source.

05 / Provenance

Drawn, not traced.

The work began with file inventories, export tables, and observable behavior — then became a new machine with its own architecture.

No engine code was decompiled. DSP algorithms follow published technique: PolyBLEP oscillators, RBJ biquads, TPT state-variable filters, FDN reverberation, look-ahead limiting, STFT analysis, and granular overlap-add. Where a reference behavior is not publicly knowable, REDRAW ships a documented equivalent-class implementation and claims no bit-identical output.

No third-party presets, samples, fonts, icons, artwork, or project files are bundled. The only legacy strings shipped are exact-match keys in the load-time compatibility table; they are never displayed as current names.

06 Deliberate limits

What it does not do. Yet.

These are implemented behaviors, not silent failures. A smaller honest surface is easier to trust than a broad claim with holes in it.

Playlist audio, MIDI and automation clips are placeholders
Pattern clips produce scheduled events. Audio, MIDI and automation blocks are editable placeholders in this phase and do not route audio or events. They are visible in the playlist, but they are not yet part of the render.
Send levels exist in the model, not as per-strip knobs
Four sends exist in the project and engine model. The mixer draws the strips, inserts and master; it does not yet draw a send knob on every strip. The routing is real, the control surface is incomplete.
Peak meters are instantaneous
Meters show post-insert, pre-master peaks and decay with the control block. There is no peak-hold and no loudness history yet.
VST hosting is partial
VST2 effects are hosted in-process on Windows through a locally declared ABI. VST3 bundles are discovered and probed, but their COM runtime is not hosted. Hosted instruments, MIDI to plug-ins, out-of-process isolation, and crash-safe third-party chunk ownership remain future work. No third-party plug-in is bundled.
There is no MIDI clock output
SMF type 0/1 import and export at 960 PPQ, live input, recording, CC/pan capture and panic are implemented. MIDI clock output is not.
Automation lanes are global; playlist blocks do not reference them
Project lanes support linear, smooth and step segments with tension, and route at control rate. Playlist automation blocks are placeholders. There is no LFO or shape generator for automation yet.
Pattern clips do not time-stretch
Pattern clips support repeat, transpose and velocity gain. Time-stretch is not applied to pattern clips, and audio clip playback is not routed yet.
Sampler and Soundfont Player need your content
Default synth patches and drum kits are synthesized in code. The sampler and Soundfont player require user-supplied samples; no sample or preset library ships with REDRAW. The exported video canvas is static, and it is intentionally not a visualizer.
